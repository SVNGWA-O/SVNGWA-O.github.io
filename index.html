eNotaryRW

A digital notarization platform for Rwanda, live in production at enotaryrw.com.

Getting a document notarized in Rwanda could take days. I built eNotaryRW to close that gap. On a Java backend, a matching engine pairs each client with an available private notary suited to the document type, in real time, and holds low latency while many requests arrive at once. The React frontend carries a single secure upload workflow, with an audit trail designed to make any tampering evident.

A few decisions behind it
Java for the matching engine Java's concurrency tools have decades of production history behind them. When many clients and notaries arrive at once, I want a model I can reason about under load.
An audit trail on every document Notarized documents carry legal weight. If one is ever disputed, the record has to account for everything that happened to the file, and when.
One secure upload workflow A single path for sensitive files is easier to test, audit, and keep correct than several.

How I Work

I build for the person who
inherits the code.

01
Proven tools over novel ones
eNotaryRW's matching engine runs on Java. When many clients and notaries arrive at once, I want a concurrency model with decades of production history behind it, one I can reason about under load. For eMed's health data I chose PostgreSQL with a normalized schema, where every fact lives in exactly one place.
02
I write for the maintainer
eMed ships iOS, Android, and web clients from a single TypeScript codebase. A fix lands once instead of three times. Docker keeps the builds reproducible, so what runs on my machine is what runs on Google Cloud Platform.
03
Trust is a design input
A notarized document is only as good as its history, so eNotaryRW records what happens to every file. eMed handles health data, and HIPAA informed the schema itself rather than a checklist at the end. Harvard's Introduction to Cybersecurity taught me to consider the hostile case early, not after launch.
04
Clear writing is part of the job
Grading at Worcester Polytechnic Institute is deliberate practice for code review, since feedback only helps when it is specific enough to change the next attempt. Fielding a program's email and phone questions taught me to explain technical detail to people outside engineering, which is most of the people software serves.
